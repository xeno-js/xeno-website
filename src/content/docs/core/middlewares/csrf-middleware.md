## What Is CsrfMiddleware?

`CsrfMiddleware` is a Xeno Presentation middleware that validates a configured
CSRF value before processing state-changing HTTP requests. It reads the CSRF
value from the current request context and compares it with the value supplied
when the middleware was registered.

If the value is missing or does not match, the middleware returns a `403
Forbidden` response and stops the CompositeMiddleware chain. Requests using
other HTTP methods continue to the next middleware.

## Which HTTP Methods Does It Validate?

The middleware validates these methods:

- `POST`;
- `PUT`;
- `DELETE`;
- `PATCH`.

The method comparison is case-insensitive because the middleware converts the
incoming method to uppercase before checking it. Methods such as `GET`, `HEAD`,
and `OPTIONS` are not validated by `CsrfMiddleware` and are forwarded through
`next()`.

## How Does CSRF Validation Work?

For a state-changing request, `CsrfMiddleware` performs the following steps:

1. It reads the current context through
	 `IRequestContext.getContext()`.
2. It obtains the CSRF value from `context.network.csrf`.
3. It checks that the value is defined.
4. It compares the request value with the configured value without regard to
	 letter case.
5. It calls `next()` when the values match.
6. It returns a forbidden error response when the value is missing or invalid.

The middleware receives the expected value through its constructor. It does not
read the raw HTTP headers directly; header extraction and request-context
creation are handled by earlier infrastructure middleware.

## How Is It Configured?

`MiddlewareModule` registers `CsrfMiddleware` when `MiddlewareConfig.csrf` is
defined. The configured value is passed to the middleware constructor.

```typescript
import { AppBuilder } from '@xeno-js/core'
import type { AppRegistry } from './registry'

const builder = new AppBuilder<AppRegistry>()

builder.addMiddlewares((config, env) => {
	config.csrf = env.getOrThrow('CSRF_TOKEN')
})

const container = await builder.build()
```

When `config.csrf` is `undefined`, `MiddlewareModule` does not register
`CsrfMiddleware`, so the middleware is not included in the composite chain.

## What Happens When Validation Fails?

When the CSRF value is missing or invalid, the middleware returns an error
generated by `HttpHelper.error`. The response contains:

- `ERROR_CODES.FORBIDDEN` as the error code;
- the standard forbidden error message;
- the detail `CSRF header is missing or invalid`;
- the request path;
- the current correlation ID, request ID, and span ID when available;
- the request format from the current context, defaulting to
	`application/json`;
- `STATUS_CODES.FORBIDDEN` as the HTTP status.

The middleware does not call `next()` after a failed check. The controller and
all later middleware therefore do not process the rejected request.

## Where Does It Run in the Middleware Chain?

`MiddlewareModule` appends `CsrfMiddleware` after the optional
`MethodCheckMiddleware` and before the optional `RateLimitMiddleware` and the
always-registered `AuthenticationMiddleware`.

The effective order depends on the enabled configuration:

```text
RequestContextMiddleware
	-> OptionsMiddleware (optional)
	-> MethodCheckMiddleware (when routeRegistry is defined)
	-> CsrfMiddleware (when csrf is defined)
	-> RateLimitMiddleware (when a rate-limit option is defined)
	-> AuthenticationMiddleware
	-> Controller or Handler
```

An `OPTIONS` request can be completed by `OptionsMiddleware` before reaching
`CsrfMiddleware`. A `GET` request reaches later middleware without a CSRF
comparison.

## Dependencies and Constraints

`CsrfMiddleware` receives these constructor dependencies:

- `IRequestContext<RequestContext, ApplicationRegistry<unknown>>`, used to read
	request metadata and the extracted CSRF value;
- the configured CSRF string, used as the expected value.

The current implementation has these constraints:

- the CSRF value must already be available at `context.network.csrf`;
- only `POST`, `PUT`, `DELETE`, and `PATCH` are checked;
- comparison ignores letter case but does not otherwise normalize the value;
- a missing or invalid value returns `403 Forbidden`;
- the middleware does not generate, rotate, or persist CSRF tokens;
- the middleware does not authenticate the caller or apply authorization
	policies.
